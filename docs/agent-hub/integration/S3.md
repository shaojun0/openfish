### 1.1 ⚠️ 关于 `findings_bp.before_request(...)`（待接线）

```python
findings_bp.before_request(require_permission(FINDING_READ))
```

## 4. 与 S4 的接口约定（§9.5 findings schema）

**校验归属**：§9.5 的 JSON 由 **S4 负责用 pydantic 校验**；校验失败的任务标
`failed`、**不写 finding**。S3 的 `ingest` 假定拿到的已经是校验过的 mapping，
只做**语义**检查（缺 `rule_id`/`file_path`/`symbol` 抛 `FindingsError`）。

### 4.1 `ingest` 接受的形状（每条 finding）

```json
{
  "rule_id": "backend.no-typing-optional",
  "level": "blocking",
  "severity": "medium",
  "file_path": "backend/services/foo.py",
  "symbol": "FooService.bar",
  "line_hint": 42,
  "title": "…",
  "detail": "…（引用历史 issue 时写 #1234）",
  "context_key": "",
  "evidence": [{"kind": "issue", "number": 1234, "relation": "mentions"}]
}
```

- 必需：`rule_id`、`file_path`、`symbol`（`ingest` 会再检查一次并 400）。
- `level` 缺省 `debt`，只能是 `blocking|debt`；`severity` 缺省 `medium`，
  非法值退化为 `medium`（S4 的 schema 应先把非法值挡掉）。
- `context_key` 缺省空串；**只有**「同一位置同一规则确实算两个问题」时才让规则填
  （§4.4，例：`debt.duplicate-implementation` 的第二处路径）。
- `line_hint` / `commit_sha` / 时间 / 文本摘要**都不进 fingerprint**，只做展示。
- `evidence[].number` 目前**不会**写进 `finding_evidence`（需要 repo_issue 主键，
  由 S2 负责解析）；`evidence[].repo_issue_id` 给了才落库。S2/S4 接好解析后
  直接把 `repo_issue_id` 塞进来即可，S3 侧无需改动。

### 4.2 runner 调用的两个入口

```python
# 1) run 开始时创建 ReviewRun（S4 负责），拿到 run_id
# 2) 产出 findings 后：
from services.findings import ingest
from services.review_policy import load
result = ingest(
    repo_id,
    run_id,
    payload["findings"],
    session=session,
    drift_adapter=GitDriftAdapter(checkout_dir),   # 可选：让 §6.2 条件1 生效
    base=base_sha,
    head=payload["run"]["commit_sha"],
    run_context={"policy": load(checkout_dir)},     # 让 §6.2 条件3 生效
)
# result == {"new": n, "matched": n, "reactivated": n, "finding_ids": [...]}
```

- `run_id` 必须是**已存在**的 `review_runs` 行；否则 `FindingsError`（I5：
  agent 产出必须能追到 `review_run_id`）。
- `ingest` 会就地累加 `ReviewRun.findings_new / findings_matched`，run 状态仍由
  S4 负责收尾。
- 不传 `drift_adapter`/`base`/`head` 时，条件 1（代码漂移）不参与本次判定；
  到期与升级照常。runner 手上有只读副本，**应当**传，否则「代码改了但人已
  acknowledge」的 finding 不会自动重开。

### 4.3 其他 S4 相关

- `POST /api/v1/findings/<id>/fix` 已按 S0 实际签名入队：
  `AgentQueue(engine).enqueue(repo_id, kind="fix", payload={finding_id, repo_id,
  rule_id, file_path, symbol, fingerprint, review_run_id}, priority=0)`，返回
  `{"finding_id","task_id","kind":"fix","queued":true}`。S4 的 worker 领取 `fix`
  任务时，payload 里的字段就是上面这些。
- S3 不判定规则、不生成修复分支；`autofix_allowed(rule_id, policy)` 是给 runner
  判断「这条规则能不能自动改」用的（§6.4，默认 false）。

## 5. 语义说明与已知限制

### 5.1 §6.2 条件 3（升级）是「规则级」判定

阈值按**同规则在本仓的 `open+acknowledged+wontfix` 总数**判定。因此实现是：
一批 findings 折进去之后，对**该规则所有仍处于 deferred 的 finding** 做一次扫描，
超过 `escalation.rule_count_threshold` 就把它们全部重开为 `open`（清空 owner/due，
记 `FindingEvent(reason="escalation")`）。触发这一次的 run 本身可能就是报的另一个
symbol——这是刻意的：升级说的不是某一条 finding，而是这条规则在本仓已经不健康了。

### 5.2 `Finding` 缺少 `stop_reason` 列（待接线，非阻塞）

§6.2 需要一个「人工声明：这条我接受风险，别再自动重开」的开关。
`services.findings` 已经按 `getattr(finding, "stop_reason", None)` 读取它：
**列不存在时该功能静默失效**（只是每次都当成没设置），其余行为不受影响。

要启用，请在 `models/agent_hub.py` 的 `Finding` 上加
`stop_reason: Mapped[str | None] = Column(String(64), nullable=True)` 并在
`models/agent_hub_migrate.py` 的幂等 ALTER 列表里加一行。这是 S0 的文件，
S3 按纪律没有改。

### 5.3 fingerprint 有两处实现，**值已由门禁钉死**

`models/agent_hub.py::fingerprint`（S0）与 `services/findings.py::fingerprint`
（S3）都实现了 §4.4。S3 的这份走 `services/digest.compute_sha256`（符合
「SHA-256 只有一份实现」）；S0 那份直接调了 `hashlib.sha256`。
两者的**取值**由 `scripts/check_findings.py` 断言必须逐字节相同，所以不会出现
「同一 finding 两个身份」。

建议（不阻塞）：把 S0 那份改成 `services.digest` 的调用，或让双方都只保留一处。
本切片不改 `models/`。

### 5.4 已知边界

- `repo` 过滤参数接受纯数字 id 或 `<owner>/<name>` slug；slug 会查 `repos` 表。
- `GET /api/v1/findings` 的 `limit` 上限 1000、默认 200；响应带 `total`。
- `PUT /api/v1/policies/<slug>` **不落盘**：返回校验后的规范化 YAML 与
  `policy_hash`，由人走 PR 提交。builtin-default 是只读的，不能靠这个端点
  「变出」一个 policy 文件。
- `exceptions[*].due` 必须**严格大于今天**；引用未知 `rule_id` 的 exception
  不致命，出现在响应的 `warnings` 里（§7.3）。
- `policy_hash` 只对**语义内容**（version/defaults/rules/exceptions/escalation）
  做规范化哈希：改注释、改缩进、换 key 顺序都不变；改内容才变。
  `hash_changed(None, cur) == False`——首次 run 没有前值，不算「不可比」。
