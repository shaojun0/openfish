## ③ 依赖的 API 与对外 API

### 3.1 依赖 S0（真实 API）

`routes/agent_tasks.py` 用 `services.agent_queue.AgentQueue`（S0 已落地），
绑定到 `current_app.extensions["db_engine"]`，并在
`current_app.extensions["agent_queue"]` 上缓存一个实例：

```python
AgentQueue(engine).enqueue(repo_id, *, kind, payload, priority, max_attempts, scheduled_at) -> int
AgentQueue.retry(task_id, *, reason="manual retry") -> bool     # failed|dead → queued
AgentQueue.cancel(task_id, *, reason="cancelled") -> bool       # queued|leased|running → dead
AgentQueue.get(task_id) -> dict | None                          # AgentTask.to_dict()
AgentQueue.session() -> Session                                 # 路由自行 join Repo / ReviewRun
```

- **列表没有队列方法**：`GET /api/v1/agent/tasks` 在路由里用
  `select(AgentTask, Repo.slug).join(Repo, …)` + `func.count` 做 `repo`/`status`
  过滤与分页（`AgentTask.to_dict()` 只有 `repo_id`，路由补 `repo` slug）。
- `AgentTask.to_dict(include_payload=False)` 提供
  `id/repo_id/kind/status/attempts/max_attempts/priority/result_ref/error/时间戳`。
- `task_log` 用 `queue.get()` + 一次 `ReviewRun`（`agent_task_id` 最新一条）取
  `log_ref`。
- 枚举全部来自 `models/agent_hub.py`（`TASK_STATUS` / `TASK_KIND`），路由不写散字符串。

### 3.2 依赖 S3（真实 API）

**policy**：`AgentRunner(policy_parser=...)` 接一个
`Callable[[str | None], PolicyView]`；`None` 表示仓库没有 policy 文件，
**parser 必须自己返回内建默认**，这样 `policy_hash` 与 S3 完全一致：

```python
from services.agent_runner import PolicyView
from services.review_policy import builtin_default, parse_document, parse_yaml

def policy_parser(text: str | None) -> PolicyView:
    if text is None:
        doc = builtin_default()                       # S3 的只读默认
    else:
        doc = parse_document(parse_yaml(text), source="file")
    return PolicyView(
        source=doc.policy_source,                     # "file" | "builtin-default"
        hash=doc.policy_hash,
        max_findings_per_run=doc.defaults.max_findings_per_run,
        raw=text,
        warnings=tuple(doc.warnings),
    )
```

**findings 入库**：runner **不**去重。平台用 S3 的
`findings.ingest(repo_id, run_id, findings, *, session, …)`；`findings` 直接吃
§9.5 的条目，所以把 `Result.findings` dump 出来即可：

```python
from services.agent_runner import FindingsSink
from services import findings

sink = FindingsSink(
    ingest=lambda task_id, result: findings.ingest(
        repo_id, run_id, [f.model_dump() for f in result.findings], session=session
    )
)
```

`repo_id` / `run_id` / `session` 由 worker 的 handler 闭包提供（handler 知道自己在
跑哪个 `ClaimedTask`）。未接线时只记日志，不会假装入库。

### 3.3 依赖 S2 / S1

S2（`services/repo_context.py`）提供检索，返回的 `text` 已经把 issue 正文用
`wrap_untrusted` 包好，`items` 只有元数据：

```python
from services import repo_context

def search_fn(workdir, *, finding, commit_sha, context):
    result = repo_context.search(
        session, repo_id=repo_id, q=f"{finding['file_path']} {finding['symbol']}",
        kind="issue", limit=5,
    )
    evidence = [
        {"kind": item["kind"], "number": item.get("number"), "relation": "mentions"}
        for item in result["items"] if item.get("number")
    ]
    return {**finding, "evidence": [*finding.get("evidence", []), *evidence]}
```

`services/agent_runner.wrap_untrusted` 是 S2 那个实现的薄委托（lazy import），
不要另写第二份；系统提示词用 S2 的 `UNTRUSTED_PREAMBLE`。

`open_pr_fn(workdir, *, branch, base, title, body) -> str`；在没有之前，fix 任务会以
`AgentRunnerError("未配置 PR 创建器")` 失败——这是刻意的（不虚构 PR）。
review 模式不依赖它，可以先跑。

### 3.5 运行时装配（worker handler 的推荐写法）

S0 的 `Worker` 已经负责 `running → done|failed` 的状态迁移，所以**用
`FindingsSink`，不要用 `DbTaskSink`**（后者会自己写 task 行，和 Worker 抢）：

```python
from services.agent_queue import ClaimedTask
from services.agent_runner import (
    AgentRunner, AgentRunnerError, FindingsSink, SubprocessRunnerAdapter, TaskRequest,
)

def handler(claimed: ClaimedTask) -> str | None:
    payload = claimed.payload_dict()
    runner = AgentRunner(
        sink=findings_sink,                       # 见 §3.2
        models_file=settings.hub.models_file,
        policy_parser=policy_parser,              # 见 §3.2
        adapter=SubprocessRunnerAdapter(
            review_fn=review_via_dsh,             # 见 §④
            search_fn=search_via_context,         # 见 §3.3（S2）
            open_pr_fn=open_pr_via_forgejo,       # 见 §3.3（S1，可暂缺）
        ),
    )
    outcome = runner.run(TaskRequest(
        task_id=str(claimed.id),
        repo_url=clone_url_for(claimed.repo_id),  # S1
        commit_sha=payload["commit_sha"],
        kind=claimed.kind,
        branch=payload.get("branch"),
    ))
    if outcome.status != "done":
        # Worker 捕获异常后调用 queue.fail()，任务落到 failed 并带上原因。
        raise AgentRunnerError(outcome.error or "agent run failed")
    return outcome.result_ref
```

`AgentRunner.sweep()` 由 worker 每轮顺带调用（或在宿主 cron 里单独调），执行 24h 回收。

## ④ 沙箱执行 DSH 的形态（§13 开放问题 5 的选择）

**选择：runner 容器内单进程 headless；runner 容器自己跑队列 worker。**
完整理由与拓扑见 `docker/runner/README.md` §2，摘要：

- runner 容器执行 `python -m services.agent_queue worker --loop`（S0 的 CLI），
  每个任务在本容器内的 `/work/<task_id>` 用 subprocess 执行
  （`git` clone/fetch + headless 模型调用），**不挂宿主 docker socket**、
  不按任务起容器。
- 「容器边界 = 沙箱边界」，与 §9.1 的 worker 边界重合，没有第二套编排；任务间
  隔离由每任务独立目录 + 容器级 `cpus/mem/pids/read_only/cap_drop` 保证。
- 模型调用通过注入的 `review_fn` 在容器内以 headless 子进程运行；它读
  `OPENFISH_MODEL_*`（由 `build_model_env` 从只读挂载的 `model_routes.json` 解析），
  `finally` 清空，不落盘、不落明文日志。
- 未来要更强隔离时，把本镜像当模板由平台按任务 `docker run`，换一个
  `RunnerAdapter` 实现即可，`agent_runner.py` 无需改动。

## ⑤ 需要 `config/` 增加的环境变量

运行时现在直接读扁平环境变量（`services/agent_runner.py` 的 `configured_*()`）。
集成阶段把它们提升为 `config/hub.py::HubConfig` 字段（pydantic-settings 默认按
字段名大写匹配，扁平名字天然继续可用）：

```python
# config/hub.py::HubConfig
    agent_work_root: str = Field(default="/work", description="每任务工作目录根（§9.2）")
    agent_work_retention_seconds: int = Field(default=86400, description="结束后的保留秒数，默认 24h")
    agent_gate_timeout: int = Field(default=120, description="每个 gate 的独立超时（§9.4）")
    agent_max_findings: int = Field(default=50, description="单次 run 的 finding 上限")
    agent_concurrency: int = Field(default=1, description="worker 最大并行任务数（S0 消费）")
    agent_model_route: str = Field(default="", description="指定模型路由名/model/alias，空取第一条启用")
```

| 环境变量 | 默认 | 消费方 |
| --- | --- | --- |
| `AGENT_WORK_ROOT` | `/work` | `configured_work_root()` |
| `AGENT_WORK_RETENTION_SECONDS` | `86400` | `configured_retention_seconds()` / `sweep_workdirs` |
| `AGENT_GATE_TIMEOUT` | `120` | `configured_gate_timeout()` |
| `AGENT_MAX_FINDINGS` | `50` | `configured_max_findings()` |
| `AGENT_CONCURRENCY` | `1` | S0 worker（本切片不读） |
| `AGENT_MODEL_ROUTE` | 空 | `AgentRunner(model_route=…)` 的部署级默认 |

提升后建议把 `configured_*()` 改成「settings 优先、env 兜底」；本次为保持离线门禁
不 import `config` 而暂用 `os.environ`（`config` 会拉起 pydantic-settings 单例）。
