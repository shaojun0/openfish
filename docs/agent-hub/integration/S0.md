## 2. `auth/permissions.py` 的接入（精确改动）

`check_permission_catalog.py` 用 `getattr(auth.permissions, <名字>)` 反解 guard 的
参数，`check_permission_labels.py` 记的是 AST 里的**裸名字**。因此两个门禁都要求这
8 个**常量**可以从 `auth.permissions` 命名空间取到——只把字符串并进 `BUILTIN` 是不够的。

改动一：文件顶部（`APP_READ = "app:read"` 之后）加一段再导出：

# 参数，check_permission_labels.py 记的是 AST 裸名字——guard 里写

    REPO_WRITE,

改动二：在 `BUILTIN: dict[str, tuple[str, str]] = { ... }` **之后**（同一模块层）
合并目录条目：

```python

改动三：把 8 个常量加进本文件末尾的 `__all__`（保持"常量集中"的语义）：

### 2.2.1 routes 里的**重复常量必须删掉**（集成时最容易漏的一步）

集成前的实测结果：S1–S4 的 routes 目前各自在本文件里**重复定义**了权限字符串
（担心 S0 未落地），例如

```

**S4 的接线方式**：`Worker(queue, handler=your_runner)`；handler 返回
`result_ref`（写进 `agent_tasks.result_ref`），抛异常即视为本次尝试失败，走
`fail()` 的重试/死信路径。队列本身不 import runner，也不做调度策略。

状态机与不变式：

```
queued → leased → running → done | failed* | dead
                    ↑                    │
                    └── reclaim_expired ─┘  (attempts+1, backoff 进 scheduled_at)
```
\* `fail()` 在 `attempts < max_attempts` 时回到 `queued`（不是 `failed`）；
`failed` 预留给 runner 显式判定的"不可重试失败"，`retry()` 同时接受 `failed|dead`。

领取语义：SQLite 走 `BEGIN IMMEDIATE`（写锁前移，避免 deferred→write 升级竞争），
PostgreSQL 走 `FOR UPDATE SKIP LOCKED`。已用 4 进程 × 20 任务的竞争测试验证：
20 次领取各不相同、无 `database is locked`。
